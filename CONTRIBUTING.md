# Contributing

Use fictional or explicitly public material in examples. Do not submit real authority inventories, raw credentials, private code, or confidential deployment snapshots.

Keep changes focused on the whole-system discovery, read-only deployment metadata collection, clarification, authority analysis, visual reporting, evidence handling, and fictional examples. Preserve model independence and a dependency-free CLI. Run the tests and validate the worked example before submitting a pull request.

Changes to the report format must update the JSON Schema, validator consistency rules, format guide, and example together. Do not turn successful artifact validation into an architectural security verdict.
