# 3. Challenge, reconcile, and deliver

Perform a fresh review pass (same host agent by default; no automatic delegation). Attempt to disprove every claimed separation. Follow administrator, deployment, credential-read, impersonation, recovery, policy mutation, contract upgrade, token allowance, alternate recipient, generic execution and external-provider paths. Check every action's alternative entry points and asynchronous recovery paths.

Challenge source-vs-deployment parity, environment/account provenance, capture timestamps, effective permissions rather than nominal roles, and whether several apparently independent approvers share recovery or administrative control. Look for implicit OR versus AND mistakes. Check that controlling an enforcer has the correct outgoing bypass edge, rather than simply leaving it as a box in the picture.

Record challenge notes per boundary; `supported` means the model and available evidence withstood this pass, not that the system is certified. Complete the challenge using all available evidence even when a separate provider fact is inaccessible; keep that dependency explicit in the graph, coverage and remaining checks. Do not mark an unperformed challenge supported. Review coverage omissions and exclusions explicitly. Never delete gaps, relabel source evidence as deployment evidence, or exclude a relevant surface to pass validation.

Continue until every conclusion is supported or blocked by specific information/access only a human can provide. Generic uncertainty is work remaining for you, not a finished outcome. `validate` and both renderers refuse delivery while uncovered gaps or agent-only review/modeling tasks remain. For a real human dependency, first exhaust available authorized checks, ask the user, and attach a scoped `human_blocker` to the open question. It must cover every dependent gap, not merely the question itself. Do not use a blanket request to excuse unrelated unknowns. The viewer leads with **Attack paths found** and **Specific input required**. A report waiting on human input is not a completed investigation.

For findings, show how the starting compromise reaches the consequential action, with evidence and all additional approvals required at each step. Do not label a missing path as a safety finding. Keep the reasons for ruled-out paths in supporting evidence. A completed review with no findings says **No attack paths found within the reviewed scope.** If human input is still required, state that the investigation remains pending instead. Observed authority is not a demonstrated exploit, and one establishing path is not an exhaustive list of alternatives.

Run `python3 TOOL/boundary_map.py validate REVIEW/report.json`. Resolve every `Agent work remains [gap-id]` diagnostic through investigation or an eligible human request. Repeat the affected investigation, reconciliation, and challenge after answers arrive; do not rerun identical checks indefinitely while waiting on a human. Then run `render REVIEW/report.json --out REVIEW/map.html`. Repository paths are loaded from workspace.json. Fix structural/evidence errors; never invent evidence or assert deployment state to pass validation. Open the local standalone HTML for visual QA and deliver the attack paths, the map, and any exact human requests needed to finish. The HTML works offline and contains no external scripts or uploads. Do not commit private reports to this public tool repository.
